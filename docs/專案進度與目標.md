## 一、專案目標（現行方向）

將 **Dual-agent** 升級為**整間公司的 AI Agent 平台**，服務每位員工的個人 AI 助理，並集中管理公司資料與安全防護。

| 支柱 | 說明 |
|------|------|
| **個人 AI 助理（CAI）** | 任務規劃、查資料、開連結、多輪對話；每人有私人記憶與偏好 |
| **組織關係圖譜** | 員工、部門、匯報線、協作／聯絡關係（「找誰、誰負責什麼」） |
| **公司知識圖譜** | SOP、政策、文件、網頁等結構化入庫與 RAG 檢索 |
| **訊息防詐（DAI）** | 簡訊、Email、通知、連結之風險審查（0–100 分與建議動作） |

### 架構原則（不變）

- **CAI** 為任務主控，**不直接寫入**底層資料庫。
- **DAI** 為安全審核、知識入庫、唯讀檢索的唯一受控入口。
- **寫入**公司記憶：僅 `secure_ingest`（規劃中）。
- **讀取**：`call_dai` / `guarded_retrieval` / `guarded_org_lookup`（規劃中）唯讀。
- **網路 raw data** 一律先經 DAI 消毒／審核後才可入庫或回傳正文。

### 資料隔離（預設模型）

- **個人層**：對話摘要、偏好、個人待辦（per `employee_id`）。
- **公司共用層**：組織圖、知識庫（依角色／部門過濾可見範圍）。

詳細架構見 [`flow.md`](../flow.md)、[`project.md`](../project.md)。

## 二、系統架構概覽

```
使用者（員工）
    │
    ▼
Ingress 正規化 ──► Memory / Context Pack
    │
    ▼
Planner LLM ──► Todo 佇列 ──► Executor（每次 todos[0]）
    │                              │
    │                    ┌─────────┴─────────┐
    │                    ▼                   ▼
    │              CAI 技能            call_dai → DAI
    │         search_web / weather   防詐 DAG / 未來：知識·組織檢索
    │         open_url / fetch_url
    │                    │
    └──────────── Replan LLM ◄────────┘
                        │
                        ▼
                  Final Answer
```

| 層級 | 目錄 | 職責 |
|------|------|------|
| CAI | `dual_agent/cai/` | Planner、Executor、Replan、Ingress 校正、個人記憶 |
| DAI | `dual_agent/dai/` | 風險評分 DAG、UEBA、毒樣 Chroma、未來 memory/org |
| 共用 | `dual_agent/ingress.py` | 輸入分類（意圖／待審正文／動作指令） |

## 五、已知問題

### 5.1 複合動作被誤排防詐（Phase 0 待修）

**案例**：`搜尋台北今天天氣，再幫我開 https://github.com`

| 現況 | 預期 |
|------|------|
| 1. `call_dai`（整句當 artifact） | 1. `weather` 或 `search_web` |
| 2. `open_url_readonly` | 2. `open_url_readonly` |
| DAI 風險 60/100（假陽性） | 不應進 DAI |

**根因**：Ingress 因句中含 URL 將整句升格為 `CHECK` + `requires_dai`（[`ingress.py`](../dual_agent/ingress.py) L506 附近），Planner 依此排 `call_dai`。

**與開 URL 交給 DAI 無關**——`open_url_readonly` 仍在 CAI；問題是工作指令被當成待審簡訊。

### 5.2 其他限制

- Executor 每次只跑 `todos[0]`，多步任務依賴 Replan 接續。
- `MAX_EXECUTOR_STEPS` 預設 3、`MAX_REPLAN_ITERATIONS` 預設 5。
- 多步 todo 整合測試仍不足。

### MVP 驗收標準

1. 兩位不同 `employee_id` 對話記憶互不干擾。
2. 可問「XX 部門主管是誰」（組織圖）。
3. 文件入庫後可依權限 RAG 問答。
4. 簡訊仍出風險卡；工作指令不誤觸防詐。
5. 寫入僅 `secure_ingest`；CAI 不直寫公司圖譜 DB。
