## 問題摘要與使用者影響

銀行面 LR（`lr_bank_v0_gd`）已離線訓練，但 **DAI 管線仍只用人工權重融合**，上線／demo 看不到 ML 分數與 `p_fraud`。需要可切換的 `DAI_RISK_FUSION_MODE=ml_lr`，並保證規則硬擋不被 ML 洗低；同時 **legacy 回歸不可壞**。

## 根因

- `step_fuse_risk_and_ueba` 固定呼叫 `fuse_risk_score_weighted`
- 無 `fuse_risk_score_ml`、無 env 開關、無模型載入路徑

## 修正策略

1. `config`：`dai_risk_fusion_mode()`、`dai_ml_model_path()`（預設指向 `data/risk_models/lr_bank_v0_gd/model.pkl`）
2. `verdict`／新模組：`fuse_risk_score_ml` — 特徵抽取 → `predict_proba` → 0–100；`r_rules|r_threat_intel >= 85` 硬擋
3. `step_fuse_risk_and_ueba`：依 mode 分支；`risk_fusion` 寫入 `mode` / `p_fraud` / `model_path`
4. `ml_*` 時 `semantic_floor` 不當主抬分（僅 hard guard + UEBA 護欄）
5. **LLM 規劃為主、validate／規則為底線** 不變；本變更只動 DAI 融合層

| group | 用途 |
